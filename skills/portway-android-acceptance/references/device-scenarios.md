# Сценарии для составления ручного протокола

Выбирай нужную область, затем сверяй полный TC и критерии в актуальном DOC-057. Эти последовательности помогают исполнению, но не отменяют деталей TC.

## Push и апрув — TC-012/032, DOC-061 §§ 4/7

1. Закрепить APK, установку, серверные возможности и безопасное действие. Зафиксировать телефон/ОС, разрешение уведомлений, активное устройство и синхронизацию часов. Не включать FCM registration token в evidence.
2. Для каждого из 3 background trials вернуть приложение в фон обычным Home, создать отдельный pending approval на сервере и записать server deadline/время отправки. Наблюдать реальное системное уведомление, записать receipt/tap, открыть его до deadline, проверить auth→GET latest и актуальные args/state.
3. Повторить 3 normal terminated trials, явно записав способ завершения процесса и доступное наблюдение process state. Не использовать force-stop через настройки как эквивалент normal terminated. Если состояние процесса не подтверждено, такой trial не объявлять подтверждённым terminated.
4. Проверить истёкшее уведомление, повторный tap, истёкшую auth/device revoked и другую installation: старый payload не разрешает действие. Для foreground убедиться в отсутствии двойного уведомления.
5. Отдельно проверить объяснение перед permission, отказ, дальнейшее включение, rotation/unlink по допустимым операциям API. Не смешивать эти края с шестью основными trials.
6. Сверить критерий 6/6 и сроки с текущим TC-012/ПМИ. Force-stop вынести как ограничение доставки до ручного открытия, а не исправлять результат имитацией notification.

## SSE — TC по DOC-057, DOC-036 `#sse`

В реальном run наблюдать разрыв и восстановление сети, повтор event, cursor/gap и history expired через разрешённые средства тестового стенда. Указать, как создано условие, и подтвердить dedupe, snapshot/resync, видимый текст состояния. Отзыв устройства должен убрать возможность действий и завершить соответствующий поток.

Для количественной приёмки применять отдельный ПМИ: реальные HTTPS и APK, независимые выборки, server commit/display timestamp, offset/погрешность и сырые данные. Одно измерение или стабильный fake stream недостаточны. Если стенд не умеет безопасно создать gap/retention, зафиксировать BLOCKED вместо правки рабочей БД.

## SAF и перенос — TC-015/026/032, DOC-038

Экспортировать выбранную версию через системное «Сохранить документ»; отменить picker и повторить. Импортировать валидный тестовый ZIP через системный picker; проверить staging→preview→mapping. Проверить unresolved и отсутствие активации/запуска до разрешения. Проверить отмену и потерю сети без двойного импорта. Невалидные/превышающие лимиты пакеты брать из допустимых тестовых файлов по SRS/DOC-038, не из личных данных телефона.

Полная проверка переносимости требует ячеек host/model из DOC-057; один ZIP round trip на той же установке не закрывает её. Отметить URI permissions и отсутствие широкого разрешения на накопитель.

## Доступность и жизненный цикл — TC-003/032, DOC-061 § 8

В Dark и Light проверить ключевые изменённые экраны с обычным и 200% шрифтом, portrait/landscape, открытой клавиатурой, длинными именами/argv/ошибками. Включить TalkBack: пройти фокусом, прослушать статус/аргументы, выполнить действия. Проверить достижимость апрув-кнопок, подписи, отсутствие единственного цветового сигнала и уменьшение анимации. Задокументировать фактический масштаб/настройки телефона, не только намерение выбрать 200%.
