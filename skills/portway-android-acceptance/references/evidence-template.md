# Форма фиксации прогона

Заполняй эту структуру в принятом разделе DOC-057 § 7 и/или фактическом evidence-артефакте. Новый формальный DOC не требуется. Незаполненная форма сохраняется как план, не как выполненный прогон.

| Поле | Что записать |
|---|---|
| TC / FR / BL / UI | Проверяемый критерий и точное подмножество |
| Дата и исполнитель | Фактическое время с зоной; кто выполнил действия/подтвердил результат |
| Candidate | Commit; dirty status и безопасный diff при необходимости; APK hash/version; backend/config identity без секретов |
| Среда | Телефон, Android/API level, Play Services, сеть, permission, host/model — если относится к сценарию |
| Preconditions | Какие реальные службы доступны; какие элементы fixture; начальные auth/lifecycle/state |
| Действия | Команды/ручные шаги в фактическом порядке; роль каждого исполнителя |
| Expected / actual | Наблюдения и измерения; для непроверенного actual — явно «не выполнено» |
| Корреляция | Безопасные run/approval/event IDs, checked_at/deadline/receipt/tap и источник времени |
| Артефакты | Относительные пути/доступные URL; SHA-256 при необходимости; пометки о редактировании чувствительных полей |
| Outcome / defect | PASS / FAIL / BLOCKED / INCONCLUSIVE / NOT_RUN по смыслу DOC-057; причина, дефект, остаток |
| Повтор / принятие | Что требует нового прогона; отдельное решение владельца, только если получено |

Для основной push-выборки добавь строку на каждый trial:

| Trial | Lifecycle и подтверждение | Approval ID | Server send/deadline | Phone receipt/tap | Latest GET/state | Наблюдаемый исход |
|---|---|---|---|---|---|---|

Не заполняй строки выдуманными значениями. Отсутствующий timestamp/неподтверждённое состояние отмечай прямо; критерий нельзя считать выполненным, если эти данные нужны для его доказательства.
